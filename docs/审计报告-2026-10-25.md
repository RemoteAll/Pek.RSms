## 3. 发现（按优先级）

| 级别 | 位置 | 问题 | 影响 | 建议 |
|---|---|---|---|---|
| **P1** | `src/settings.rs:110` | `extend_map()` 每次调用都 `serde_json::from_str`；单次发送会多次调用 `extend_str`（`BaseUrl`/`Host`/`SdkAppId`/`TemplateId`/`CountryCode`/`Region`/`InsecureTls`） | 每次发送重复解析 5~10 次，产生无效分配/CPU | 在客户端构造时解析一次并缓存；或 `SmsData` 增加 `OnceLock<Map>` |
| **P1** | `src/settings.rs:23-25` | `SmsData` 派生 `Debug`，包含 `access_secret`；`SmsSettings` 同样 | `{:?}` 日志可能泄露短信平台密钥 | 手写 `Debug` 脱敏；长期可下沉 `dhrust::secret::SecretString` |
| P2 | `src/http.rs:32-55` | 重试只覆盖 `blocking_request_offthread_with` 返回的传输错误；HTTP 5xx/429 作为 `Ok(response)` 直接返回 | 与 C# `.Retry(RetryTimes)` 语义可能不一致；瞬时 5xx 不重试 | 明确策略：5xx/429 重试，4xx 不重试；补充测试 |
| P2 | `src/settings.rs:110-122` | `ExtendData` 非法 JSON 被静默忽略（返回空 map） | 实际错误被掩盖为“SdkAppId 不能为空” | `extend_map_result()` 或加载时 `warn!` 并记录原始错误 |
| P2 | `src/client/fenghuo.rs:~130` | 代理 `Id` 用 `getmilltimestamp()`，同毫秒并发可能重复 | 代理侧若按 Id 去重会误判 | 时间戳 + 随机后缀/全局计数器 |
| P2 | `src/client/lianlu.rs:~45` | 强制要求 `SignName`，但请求体从不发送签名 | 与 C# 一致但易误解；空签名时直接失败 | README/注释说明；或按平台实际要求调整 |
| P2 | `src/client/tencent.rs:162` | `url_authority` 未处理 IPv6/用户信息 | 自定义网关的极端 URL 可能签名 Host 错误 | 使用 `url` crate 解析或明确文档限制 |
| P2 | `src/client/tencent.rs` | `CountryCode` 直接拼接；号码以 `00` 开头时不会转换为 `+` | 与 C# 行为一致，但国际号码可能出错 | 文档说明；后续可加规范化 |
| P3 | `src/message.rs:76` | `mobiles` 是公开字段，直接赋值会绕过去重/拆分 | 调用方误用导致重复号码 | 增加 `validate()` 或在客户端统一规范化 |
| P3 | `src/smser.rs:132` | `send_with_code` 不检查 `IsEnabled` | 与 C# `FindByCode` 一致，但可能误发 | 文档写明；或提供 `send_with_code_checked` |
| P3 | `src/http.rs:32` | 每次尝试走 `offthread`（额外线程 + 临时 tokio runtime） | 低频可接受；高频发送有线程/运行时开销 | 文档说明；必要时提供 `*_blocking` 直调版本 |
| P3 | `src/smser.rs:68` | `settings()` 每次 clone 整份配置（含所有账号） | 账号多时每次发送多一次分配 | 可返回 `Arc` 快照或只 clone 选中账号 |

## 4. 测试缺口

1. HTTP 5xx/429 重试语义；
2. 非法 `ExtendData` JSON 的错误提示；
3. 请求超时（`Timeout`）；
4. 同毫秒代理请求 `Id` 唯一性；
5. 并发热加载（`save_settings`/`reload_if_changed` 与 `send`）；
6. 真实服务商互操作（可选，需外部凭据）。

## 6. 建议

1. **先做安全与 P1**：Debug 脱敏、`ExtendData` 解析缓存；
2. **修正 HTTP 重试语义**：5xx/429 可重试，4xx 不重试，并补测试；
3. **与 Pek.RMail 一起抽 `TomlConfigStore<T>`**；
4. **再下沉小工具**：`form_encode`、`times`、`json`、`text`；
5. 不急于把 `SmsRequest`/`SmsResult`/各服务商协议放进 dhrust：领域/协议细节应留在本库。
