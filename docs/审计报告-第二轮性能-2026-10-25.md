## 3. 性能优化点

### 3.1 `ExtendData` 每次重复解析（最大 CPU 热点）

`SmsData::extend_map()`（`settings.rs:132`）每次调用都 `serde_json::from_str`。单次发送的调用次数：

- 阿里云 5~6 次；
- 腾讯云 7~8 次；
- 烽火约 3 次；
- 连陆约 2 次。

单次解析 1.4~1.7µs；六连调 9~10µs。建议每次 `send` 只解析一次：新增 `SmsData::extend_view()`/`ExtendView`，提供 `str/bool/i64/base_url/insecure_tls`，客户端在 `send` 开头构造一次。

### 3.2 重复克隆配置/账号

`Smser::send`（`smser.rs:95`）克隆整份 `SmsSettings`，再克隆已启用账号；`create_client`（`client/mod.rs:40`）又克隆 `config` 和 `_settings`，而阿里云/腾讯云/连陆根本不用 settings。实测 settings 克隆（10 账号）1.7~2.5µs，`create_client` 2~3µs。

建议：

- 三个不用 settings 的客户端只 `config.clone()`；
- 新增 `create_client_owned(SmsData, &SmsSettings)`，`Smser` 把已克隆的账号直接交给客户端，去掉二次克隆；
- 烽火只保留代理三项，不克隆整份 settings。

### 3.3 手机号去重 O(n²)

`message.rs:232` 用 `out.iter().any(...)`；`from_numbers` 用 `mobiles.contains`。实测 100 号 20~30µs，1000 号 1.6~1.8ms。建议 `HashSet` + 保序 `Vec`，1000 号预期降到 ~50µs 量级。

### 3.4 HTTP 线程/运行时/连接

`http.rs:32` 每次尝试 `blocking_request_offthread_with`：新线程 + 新 tokio 运行时；`http_client` 每次 `TcpStream::connect`，无连接池。建议：

1. dhrust 增加 `blocking_request_auto`：不在 tokio 上下文就直接调用，省 0.2ms/尝试；
2. 中期提供持久化阻塞客户端（后台运行时 + keep-alive），降低高频短信 TCP/TLS 握手；
3. `http::post` 每次重试 `body.clone()`，大列表可改 `Arc<[u8]>`（P3）。
